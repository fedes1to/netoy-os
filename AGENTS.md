# AGENTS.md

An Alpine Linux-based bootable ISO that turns a Ventoy USB stick into a
self-contained ISO manager. The repo has two tightly coupled parts:

- **`netoy-tui/`** — a Rust TUI (ratatui + crossterm) that runs inside the
  ISO and manages ISOs on the Ventoy data partition. Tracked as a **git
  submodule** (`.gitmodules`, `https://git.fedesito.me/fedesito/netoy-tui.git`),
  not as regular source. Changes to the TUI happen in the submodule's own
  repo and are pulled in via submodule bumps.
- **The Alpine image build** (everything else) — shell scripts that compile
  `netoy-tui` with the `for-bootable` feature and assemble the ISO with
  Alpine's `mkimage.sh` tooling.

Both halves are GPL-3.

## Boot-time architecture (the core gotcha)

The whole image exists to work around one problem: booted through Ventoy,
the ISO is a *file on a USB data partition*, and Ventoy injects a userspace
hook that creates a `device-mapper` node over that partition — pinning it
read-only and breaking Alpine's boot. The solution is a two-stage "copy to
RAM" so the stick can be **unplugged after boot**:

1. **Initramfs wrapper** (`overlay/initramfs-files/init` + `netoy-copy-iso.sh`):
   copies the netoy ISO from the Ventoy data partition into a tmpfs at
   `/run/netoy-iso-ram`, attaches it to `/dev/loop0`, then **neutralizes
   Ventoy** (deletes `/ventoy/ventoy_os_param` and Ventoy's udev rules) so
   no competing dm node is ever created. Then `exec /init.orig`.
   - `init` is swapped in during ISO post-processing (see below); the stock
     Alpine init is preserved as `init.orig` and patched by
     `patch-init.orig.sh` to use `$NETOY_LOOP_DEV` instead of scanning all
     devices (the old re-mount with `-o loop` failed with "Resource busy"
     and dropped the boot into the emergency recovery shell).
   - Deliberate quirk: **never mount devtmpfs on /dev in the wrapper** —
     init.orig mounts it itself; a pre-mounted devtmpfs would fail (EBUSY),
     fall back to an empty tmpfs, and hide `/dev/loop0`.
2. **OpenRC `netoy-ram` service** (`overlay/etc/init.d/netoy-ram`, runlevel
   `boot` via `genapkovl-netoy.sh`): copies the modloop squashfs to
   `/lib/.netoy-ram/modloop.img`, unmounts boot media, removes leftover
   Ventoy dm nodes (`dmsetup remove --force ventoy vtoy ventoy2`), and
   mounts the real data partition (label `Ventoy`) read-write at
   **`/mnt/netoy`**. It stops udev first because udevd (libkmod) pins
   `/lib/modules` and would make the unmount fail with EBUSY.

Result: `/lib/modules`, firmware, and boot media all live in RAM; the TUI
finds the data partition already mounted at `/mnt/netoy`.

## Build pipeline

`./build.sh` runs `scripts/build-in-container.sh` inside an
`alpine:3.24` **podman** container (repo mounted at `/work`, submodule
source at `/netoy-tui:ro`). Steps, in order:

1. Installs tools incl. `rust cargo`; runs `abuild-keygen` and copies the
   pubkey to `/etc/apk/keys` (mkimage signs the modloop).
2. Builds the TUI: `cargo build --release --features for-bootable`, strips
   it, copies to `overlay/usr/local/bin/netoy-tui`. (The overlay binary is
   gitignored — rebuilt on every build, don't commit it.)
3. Pre-fetches the dnscrypt-proxy resolver list into
   `overlay/var/cache/dnscrypt-proxy/` (also gitignored).
4. Writes custom mkinitfs feature files: `netoy.modules` (exfat/ntfs3/vfat/
   iso9660/USB/SCSI/dm-mod/loop kernel modules) and `netoy.files`
   (losetup, dmsetup). Exports `MKINITFS_ARGS="-P /etc/mkinitfs/features.d"`
   because update-kernel looks for features in `$ROOTFS` only.
5. Runs `./vendor/mkimage.sh --profile netoy` (vendored Alpine 3.24-stable
   script; profile defined in `vendor/mkimg.netoy.sh`, base in
   `vendor/mkimg.base.sh`). The apkovl is generated by
   `genapkovl-netoy.sh` (`apkovl="genapkovl-netoy.sh"` in the profile; it
   reads `NETOY_OVERLAY` or defaults to `./overlay`, strips
   `initramfs-files/`, adds runlevels, bundles `etc usr var [root]`).
6. **ISO post-processing** (in build-in-container.sh): extracts
   `/boot/initramfs-lts` with xorriso, replaces `init`, adds
   `netoy-copy-iso.sh`, patches `init.orig`, creates the losetup symlink
   and static dmsetup, then **trims GPU firmware from the modloop**
   (nvidia + cirrus removed — ~1.3 GB uncompressed, never used by the
   text-only framebuffer UI; Intel/AMD display firmware is kept). The
   rebuilt squashfs is **re-signed** with the build's abuild key and the
   embedded signature blob in the initramfs
   (`var/cache/misc/modloop-lts.SIGN.RSA.*`) is replaced — otherwise
   modloop signature verification fails at boot.
7. Also in post-processing: a curated list of **dynamic-firmware wifi/
   ethernet drivers** (ath12k, mwlwifi, rsi, mellanox, liquidio) whose
   firmware is copied into the modloop only if the matching module exists.
   `update-kernel` misses these because modinfo lists no firmware for
   runtime-loaded firmware (e.g. AX211 wants
   `iwlwifi-so-a0-gf-a0-100.ucode`, linux-firmware ships …-89.ucode — the
   vendored `vendor/alpine-conf/update-kernel` is on PATH to fix exactly
   this family-copy behavior).

Output: `out/netoy-YYMMDD-x86_64.iso` (or `netoy-alpha-x86_64.iso`).

**Gotchas:**
- Before running, delete any stale `out/netoy-*.iso` (the script does this
  itself: a foreign-owned leftover makes xorriso fail with "Burn run
  failed"/"Permission denied").
- Host needs `podman` and the submodule initialized
  (`git submodule update --init`).
- `qemu-serial.sh` boots the newest `out/netoy-*-x86_64.iso` headless with
  `-nographic`; Ctrl+A then C → QEMU monitor, `q` quits.

## Runtime console setup

- `overlay/etc/inittab`: `agetty --autologin root --login-program
  /usr/local/bin/netoy-autologin` on tty1 (VGA) and ttyS0 (serial), plus
  plain root shells on tty2–tty6. `netoy-autologin` just does
  `exec /bin/login -f root`.
- `overlay/root/.profile` launches netoy-tui on tty1/ttyS0 (TERM=linux on
  VGA, TERM=vt100 on serial; forces 24x80 if stty reports 0x0; `stty sane`
  before and after via a trap — a panicked TUI can leave the tty in raw
  mode). Quitting the TUI drops to a root shell; the login shell respawns.
- **Two independent TUI processes run at once** (one per console) — never
  use both consoles for USB operations.
- Root login is passwordless on the local console (`overlay/etc/passwd` has
  an empty root hash).
- Kernel cmdline (from `vendor/mkimg.netoy.sh`):
  `modules=loop,squashfs,sd-mod,usb-storage,iso9660,sr_mod console=ttyS0,115200 console=tty1 debug_init`.
  `gen_volid()` overrides the ISO label to `NETOY-<release>-<arch>` (space-free,
  needed by GRUB/Ventoy and `alpine_dev=LABEL=`).

## Networking (inside the ISO)

- NetworkManager with `wpa_supplicant` default Wi-Fi backend, switchable to
  `iwd`; `nmtui` as the user front-end; NM's internal DHCP; **no dnsmasq
  and no dnscrypt-proxy in the default DNS path** — NM's default plugin
  writes the router's nameservers straight into `/etc/resolv.conf`. (The
  README still mentions dnsmasq/dnscrypt in places; git history shows the
  resolv.conf/dnsmasq story changed several times — verify against the
  overlay when touching DNS.)
- `overlay/etc/resolv.conf` is a **regular file, deliberately not a
  symlink**: NM's DNS plugin refuses to write through a foreign symlink
  (Alpine's default points at /run/resolv.conf).
- Wi-Fi backend switching goes through `overlay/usr/local/bin/netoy-backend`
  (`get|set wpa_supplicant|set iwd`), which rewrites
  `/etc/NetworkManager/conf.d/wifi-backend.conf` (source of truth) and
  restarts NetworkManager. The TUI calls it at `/usr/local/bin/netoy-backend`.
- `overlay/etc/dnscrypt-proxy/dnscrypt-proxy.toml` exists (DoH on
  127.0.0.1:53) but the package world + runlevels are what matter; the
  resolver list cache is baked in at build time for offline DoH bootstrap.
- `overlay/etc/iwd/main.conf`: iwd's own network config is left disabled —
  NM does association + DHCP, iwd only provides the link layer.

## netoy-tui internals

Rust 2024 edition, ratatui 0.30 + crossterm, single binary, no runtime
switch: the two build modes are a compile-time Cargo feature,
**`for-bootable`**. `network/mod.rs` swaps the whole implementation:
`bootable.rs` (integrated: nmtui launch, rfkill handling, Wi-Fi backend
helper, DNS test) vs `standalone.rs` (stubs). Don't add `cfg` checks inside
the UI screens — the pattern is: screen code calls
`crate::network::*` and the module dispatch handles the feature.

Key files (in `netoy-tui/src/`):
- `main.rs` — restart loop; `QuitAction::Restart` re-runs the TUI, and in
  the integrated build `Poweroff`/`Reboot` call `do_poweroff`/`do_reboot`.
- `app.rs` — `App` state machine: `Screen` (Welcome→Network→Manage→
  Download), `Focus` (Sidebar/Content, Tab switches), `BgMsg` channel for
  background workers (connectivity probe, download, DNS test, backend
  switch), `DlState` for the single download/sync job. Sidebar navigation
  skips locked screens (`unlocked()` — Download requires `online()`);
  `drain_bg` retreats from a screen that just became locked. 5-second
  auto-refresh (`AUTO_REFRESH_INTERVAL` in event.rs) rescans USB +
  re-probes network.
- `event.rs` — key dispatch. Sidebar is focused by default; letter hotkeys
  work regardless of focus. Q/Esc open a quit modal (standalone: restart/
  terminal; integrated: + poweroff/reboot).
- `connectivity.rs` — three-layer probe (interfaces via `netdev` → IP →
  DNS + HTTP GET). Probe URL: `https://example.com`, overridable with
  `NETOY_PROBE_URL` (e.g. `NETOY_PROBE_URL=http://192.0.2.1:9` simulates
  offline for tests).
- `usb.rs` — Ventoy detection via `/dev/disk/by-label` (`Ventoy` data,
  `VTOYEFI` fallback discovering sibling partitions ≥256 MiB on the same
  disk). The integrated build's `mount()` handles the "undo-trick":
  `ventoy_remount_dev()` prefers `/dev/mapper/<name>`, creates a linear
  mapper with dmsetup if Ventoy's dm is pinning the partition, and
  `trick_mounts()` unmounts iso9660/loop/ventoy mounts deepest-first. The
  standalone build uses `udisksctl`. Do not run the integrated binary on a
  desktop — it refuses non-root and touches mounts.
- `download.rs` — background ureq download to `<name>.part`, then flush to
  the stick: Linux uses `libc::sync_file_range` in 8 MB chunks so the
  progress gauge moves; every `.iso` is fsynced and the dir synced
  (`sync_usb`). `filename_of()` strips query/fragment before taking the
  basename.
- `sources.rs` — collapsible ISO source tree. Sources:
  - **links/lynx** terminal browser (fallback for everything); `links`
    preferred, `lynx` fallback; cyclable in-app with `B`; overrides
    `NETOY_BROWSER` (choice) and `NETOY_BROWSER_URL` (start page, default
    https://distrowatch.com).
  - **netoy-iso.sh** (bundled `vendor/netoy-iso.sh`) — own resolver; each
    distro function uses the most stable mechanism (stable redirect /
    autoindex + version-sort / pinned URL) and was verified to resolve a
    live ISO (HTTP 206) before being added. Arch, Alpine, Ubuntu, Debian,
    Fedora, openSUSE, Tails, Qubes, SystemRescue + Free/Open/NetBSD.
    Needs curl+wget+awk+grep (busybox provides awk/grep).
  - **Mido** (bundled `vendor/Mido.sh`, MIT © Elliot Killick) — official
    Microsoft Windows ISOs with SHA-256 verify; `MIDO_LANGUAGE` for
    non-English SKUs. Windows 11 LTSC / 10 IoT LTSC aren't in the
    consumer/eval API, so those rows open the browser instead.
  - **netboot.xyz** — only the full ISOs it hosts (Proxmox VE, its own
    menu ISO); the rest of endpoints.yml is iPXE assets.
  - SourceForge-hosted tools (GParted Live, Clonezilla, Rescuezilla,
    Hiren's) are browser links, not resolvers — Cloudflare challenges
    block scripted clients.
  - The scripts are compiled in via `include_str!` and materialised to
    `/tmp` on every launch (`materialise()` **always overwrites** — a
    stale script at the same path caused "command not found" exit 127).
  - LinuxDownloader leaves launch: resolve URL by capturing stdout, then
    in-app ureq download with live progress (no terminal handover).
    Browser/Mido: `ratatui::restore()`, run tool with **cwd = USB mount**
    (so the ISO lands on the stick; Mido gets script dir prepended to
    PATH so it doesn't `cd` away), `ratatui::init()`, kill stray
    links/lynx (`kill_stray_lynx` — they linger and keep the USB busy),
    rescan, then background `sync_usb` flush.
- `network/dns_config.rs` — DNS form (Plain/DoH/Local(dnsmasq) modes) kept
  in App even in standalone so UI code stays feature-agnostic; only `dns.rs`
  (integrated) executes anything. `dns_test()` pings 1.1.1.1 then
  cloudflare.com with captured output.
- UI in `ui/`: `mod.rs` renders sidebar + dispatches per-screen renderers
  (`ui/screens/{welcome,network,manage,download}.rs`); `theme.rs` has the
  visual theme. `render_quit_modal` is split bootable/standalone via cfg.

## Testing

- `cargo test` in `netoy-tui/` — unit tests live in-module (`#[cfg(test)]`
  in app.rs, connectivity.rs, download.rs, sources.rs, usb.rs,
  dns_config.rs). Sources tests serialize env-mutating tests via a
  process-wide mutex. `usb.rs` tests build fake `/proc/mounts` tables
  (`MountList::new_from_reader`).
- `python3 scripts/smoke.py <standalone|integrated|usb>` — pty harness in
  `netoy-tui/scripts/smoke.py`. Drives the debug binary with TERM=
  xterm-256color. **Important**: it drives the *sidebar* with arrow keys +
  Enter; comments note that letter shortcuts for navigation were never
  wired. The `usb` scenario needs a real Ventoy stick at `/dev/sdc1`
  mounted at `/run/media/fed/Ventoy` and uses udisksctl; it drops a fake
  ISO and exercises the delete flow. Requires the debug build
  (`target/debug/netoy-tui`).
- The integrated smoke scenario's checks for "impala"/"dhcpcd" reflect a
  network stack that was replaced by NetworkManager+nmtui; those keys are
  now `n`/`b`/`t` — if the smoke test fails there, it's stale, not a
  regression.

## Conventions and gotchas

- Shell scripts are Alpine/busybox-flavored POSIX sh (except vendored
  `vendor/netoy-iso.sh` tools which run under bash). `set -e` is used in
  build scripts; initramfs wrapper functions use `|| true` liberally and
  log via `netoy_log` → `/dev/kmsg` (userspace stdout isn't reliably
  visible at that boot stage).
- The initramfs lives at `/run/netoy-iso-ram` (tmpfs) after copy; the
  fixed loop device is `/dev/loop0` and `patch-init.orig.sh` is what makes
  init.orig use it.
- `overlay/usr/local/bin/netoy-tui`, `overlay/usr/local/bin/impala` (dead
  — impala was removed), `overlay/var/cache/dnscrypt-proxy/`, and
  `package-lock.json` are gitignored build artifacts — do not commit them.
- When bumping the submodule, the README at the repo root duplicates much
  of netoy-tui's README; both have drifted historically (dnsmasq, impala,
  key labels). The code and `overlay/` are authoritative.
- ISO label must stay space-free (`gen_volid` in `vendor/mkimg.netoy.sh`).
- Multi-line shell comments in these scripts use long prose to explain
  *why* (Ventoy, modloop signing, EBUSY); preserve that style — it is the
  only documentation for the boot trick.
